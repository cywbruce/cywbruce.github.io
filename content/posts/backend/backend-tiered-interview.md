## 一、计算机基础

### 1. TCP 三次握手与四次挥手（初级）

**主问：** 为什么握手是三次、挥手是四次？

**参考答案：** 三次握手让双方都确认自己和对方的收发能力正常，也能防止已失效的旧连接请求被误建立。挥手是四次，因为 TCP 是全双工的，两个方向要分别关闭：被动关闭方可能还有数据没发完，所以 ACK 和 FIN 分两次发。主动关闭方会进入 TIME_WAIT，等待 2MSL。

**追问：** 线上 TIME_WAIT 过多怎么处理？CLOSE_WAIT 过多又说明什么？（通常是自己的代码没有 close）

**定级：** 能答出 CLOSE_WAIT 一般是代码 bug → 中级的信号。

---
### 2. 进程、线程与协程（初级）

**主问：** 进程、线程、协程有什么区别？

**参考答案：** 进程是资源分配的单位，地址空间相互隔离；线程是 CPU 调度的单位，同一进程的线程共享内存；协程是用户态调度，切换成本很低，适合 I/O 密集型场景（Go goroutine、Java 虚拟线程）。

**追问：** Java 21 的虚拟线程适合哪些场景？pinning 是什么问题？

---
### 3. I/O 多路复用（中级）

**主问：** select、poll、epoll 有什么区别？

**参考答案：** select 有 fd 数量上限，每次都要拷贝 fd 集合并线性扫描；poll 去掉了上限，但仍然是线性扫描；epoll 用红黑树管理 fd，用就绪链表返回事件，复杂度和就绪 fd 数量相关，支持边缘触发（ET）和水平触发（LT）。Redis、Nginx、Netty 都基于这个模型。

**追问：** ET 模式下为什么必须配合非阻塞 I/O，并且要一直读到 EAGAIN？

## 二、接口与存储

### 4. 接口幂等（中级）

**主问：** 支付回调被重复调用了，怎么保证幂等？

**参考答案：** 用唯一业务号（订单号或请求 ID）+ 数据库唯一索引；用状态机做条件更新（`UPDATE … WHERE status = 待支付`）；也可以用去重表或 Redis `SET NX` 做前置拦截。返回结果要一致：重复请求直接返回第一次的结果。

**追问：** 前端重复提交和 MQ 重复消费怎么统一处理？

**定级：** 能讲到状态机 + 唯一约束兜底 → 中级。

---
### 5. 分库分表（中高级）

**主问：** 单表到了几千万行，什么时候拆？怎么拆？

**参考答案：** 先考虑索引、归档、读写分离、缓存。确实需要拆时：垂直拆按业务划分，水平拆选分片键（比如 user_id），用 hash 或 range 路由。拆完会带来的问题：跨分片查询（用宽表或 ES 解决）、分布式 ID（雪花算法或号段）、分布式事务、扩容迁移（双写 + 校验 + 灰度切读）。

**追问：** 订单表既要按买家查，又要按卖家查，怎么设计？

---
### 6. 分布式 ID（中级）

**主问：** 分布式 ID 有哪些方案？

**参考答案：** UUID：无序、太长，不适合做主键。数据库号段（如 Leaf-segment）：趋势递增，依赖数据库。雪花算法：时间戳 + 机器号 + 序列号，需要处理时钟回拨。Redis INCR：简单，但要考虑持久化。选择时看三点：是否需要趋势递增、高可用要求、信息泄露风险。

**追问：** 雪花算法遇到时钟回拨怎么处理？

## 三、分布式与微服务

### 7. CAP 与 BASE（中级）

**主问：** 怎么理解 CAP？实际系统是怎么取舍的？

**参考答案：** 发生网络分区（P）时，只能在一致性（C）和可用性（A）之间二选一。ZooKeeper/etcd 偏 CP；Eureka、大部分缓存偏 AP。BASE（基本可用、软状态、最终一致）是 AP 方向的工程化做法。

**追问：** 注册中心应该选 CP 还是 AP？为什么？

---
### 8. 分布式事务（中高级）

**主问：** 跨服务下单扣库存，怎么保证一致性？

**参考答案：** 2PC/XA：强一致，但会阻塞、性能差。TCC：Try-Confirm-Cancel，业务侵入大，要处理空回滚和悬挂。Saga：长事务配补偿操作。本地消息表 / 事务消息（RocketMQ）：最终一致，用得最多。实践中通常优先选最终一致，再加对账兜底。

**追问：** TCC 的空回滚和悬挂分别是什么？怎么处理？

**定级：** 能讲出方案的适用边界和对账兜底 → 高级。

---
### 9. 限流熔断降级（中级）

**主问：** 限流算法有哪些？熔断和降级有什么区别？

**参考答案：** 限流算法：固定窗口、滑动窗口、漏桶（输出速率恒定）、令牌桶（允许一定突发）。熔断：下游错误率超过阈值就断开，过一段时间进入半开状态试探恢复。降级：主动关闭非核心功能或返回兜底数据。工具有 Sentinel、Resilience4j、网关限流。

**追问：** 集群限流和单机限流怎么配合？

---
### 10. 线上 CPU 飙高排查（中高级）

**主问：** 线上 Java 服务 CPU 100%，你怎么排查？

**参考答案：** `top` 找到进程 → `top -Hp` 找到线程 → 线程 ID 转成十六进制 → `jstack` 找到对应栈；也可以直接用 Arthas `thread -n 3`。常见原因：死循环、正则回溯、频繁 GC（用 `jstat -gcutil` 看）、锁自旋。先止血（扩容、回滚、摘流量），再保留现场（dump）定位根因。

**追问：** 怎么判断是 GC 导致的还是业务代码导致的？

**定级：** 先止血再定位、能保留现场 → 中高级。

---
### 11. 可观测性（高级）

**主问：** 日志、指标、链路追踪怎么搭配使用？

**参考答案：** 指标（Prometheus）用来发现问题和告警，关注 RED/USE；链路追踪（OpenTelemetry）用来定位是哪个服务、哪一跳慢；日志用来看细节，要带 traceId 方便关联。告警要基于 SLO，避免告警风暴。

**追问：** 采样率怎么定？尾部采样有什么好处？
