## 〇、怎么问才有效

**差问法：** 「什么是观察者模式？」  
**好问法：** 「订单状态变更要通知库存、积分、消息，怎么设计？以后还要加模块怎么办？」

对照 SOLID（尤其单一职责、开闭）听候选人是否真的用过。

## 一、创建型

### 1. 单例（初级～中级）

**主问：** 写一个线程安全单例；项目里哪些东西适合单例？

**参考答案：**

- 常见写法：静态内部类、枚举（防反序列化/反射更稳）、双重检查 + `volatile`。  
- 适合：无状态工具、全局配置、昂贵且可共享的资源管理器。  
- **不适合：** 带请求状态的对象硬做成单例（成隐蔽共享可变状态）。

**追问：**

1. 双重检查为什么要 `volatile`？  
2. Spring 单例 Bean 和 GoF 单例是一回事吗？（容器管生命周期，非 JVM 唯一）  
3. 单例滥用有什么害处？

**定级：** 能写对一种安全写法 → 初级；能讲 volatile/枚举与 Spring 差异 → 中级。

---

### 2. 工厂 / 抽象工厂 / Builder（初～中）

**主问：** 「一堆 if 根据 type 创建对象」怎么重构？

**参考答案：** 简单工厂或工厂方法把创建集中；新产品用开闭方式扩展（注册表/Map + 策略）。抽象工厂：一族产品。Builder：构造参数多、有必选可选、要不可变对象时。

**追问：** 和 Spring `@Component` + 按类型注入列表有何关系？（容器当工厂）

**场景追问：** 支付渠道（微信/支付宝/银行卡）创建支付客户端——用工厂还是策略？两者如何配合？

## 二、结构型

### 3. 代理（中级，联 Spring）

**主问：** 静态代理、JDK 动态代理、CGLIB 差别？在 Spring 哪见过？

**参考答案：** 代理控制访问、加事务/日志/权限。JDK：基于接口；CGLIB：子类。Spring AOP、`@Transactional` 就是代理。自调用不走代理。

**追问：** 和装饰器有何不同？（代理重控制访问，装饰重增强功能；实现常像）

---

### 4. 装饰器（中级）

**主问：** 不修改原类，动态叠加功能（加密、压缩、缓冲），怎么做？

**参考答案：** 装饰器与被装饰者同一接口，可嵌套包装。对比继承：更灵活，避免类爆炸。Java I/O 流是经典例子。

**追问：** 和代理如何区分选型？

---

### 5. 适配器（初级～中级）

**主问：** 老接口和新系统不匹配怎么办？

**参考答案：** 适配器转换接口。对象适配 vs 类适配。项目中：封装第三方 SDK、统一支付/短信网关门面下的适配层。

---

## 三、行为型

### 6. 策略（初级～中级，高频）

**主问：** 消除业务里大段 `if-else` / `switch` 算价、算运费，怎么做？

**参考答案：** 策略接口 + 多实现 + 上下文选择（可用 Map 注册）。符合开闭：加新策略不改老分支（或只改注册）。

**追问：**

1. 策略和工厂怎么配合？  
2. 策略会不会导致类太多？何时觉得过度设计？  
3. 用枚举+方法能代替吗？边界在哪？

**定级：** 能落到代码结构 → 中级；能谈过度设计 → 冲高。

---

### 7. 模板方法（初级～中级）

**主问：** 流程固定、某几步可变（如导入：校验→解析→落库），怎么抽象？

**参考答案：** 父类定骨架，子类覆写钩子步骤。Spring 里能见到类似「回调模板」（`JdbcTemplate`、`RedisTemplate` 思想相近：固定流程，用户补差异）。

**追问：** 和策略差别？（继承骨架 vs 组合算法）

---

### 8. 观察者 / 发布订阅（中级）

**主问：** 事件发生后通知多方，解耦怎么做？

**参考答案：** 观察者：主题维护列表并通知。消息队列是跨进程发布订阅。Spring `ApplicationEvent`、Guava EventBus、MQ 都是变体。

**追问：** 同步事件里抛异常会怎样？是否该异步？顺序与丢失如何保证？

---

### 9. 责任链（中高级）

**主问：** 审批流、过滤器链、网关鉴权多层校验，怎么设计？

**参考答案：** 请求沿链传递，节点可处理或下放。Servlet Filter、Netty Pipeline、敏感词/风控流水线常见。要设计好：是否可中断、顺序、通用上下文。

**追问：** 和装饰器流水线有何不同？链太长如何排查？

---

## 四、原则与重构（高级）

### 10. SOLID 与「你何时不用模式」（高级）

**主问：** 开闭原则在你项目里的一次落地？有没有「过度设计」复盘？

**参考答案期望：** 能举真实重构（策略/插件化）；承认 YAGNI：两处重复再抽象；模式是手段不是KPI。

**追问：** 组合优于继承，你怎么理解？给一个继承滥用改组合的例子。

## 五、场景速测（直接丢给候选人）

| 场景 | 期望方向 |
| --- | --- |
| 多种导出格式（Excel/PDF/CSV） | 策略 + 工厂 |
| 日志增强、鉴权环绕 | 代理 / AOP |
| IO 叠加缓冲加密 | 装饰器 |
| 订单状态变更通知 | 观察者 / MQ |
| 审批多级 | 责任链 |
| 复杂对象构建 | Builder |
| 兼容老支付 SDK | 适配器 |

听：**有没有先澄清变化点**，再选型。
