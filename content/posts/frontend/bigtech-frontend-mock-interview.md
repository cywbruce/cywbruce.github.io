## 一面：JS 基础与手写

### 1. 闭包与内存（初级）

**主问：** 什么是闭包？闭包一定会造成内存泄漏吗？

**参考答案：** 闭包就是函数加上它定义时所在的词法环境：内层函数引用了外层变量，外层函数执行完后，这些变量也不会被回收。闭包本身不是泄漏，只有不再需要的闭包仍然被长期引用才会泄漏，比如挂在全局的事件监听没有移除，或者定时器一直没清。常见用途：封装私有变量、柯里化、防抖节流。

**追问：** `for (var i…) setTimeout` 为什么打印的全是同一个值？怎么修？（用 let 的块级作用域，或者用 IIFE 包一层）

---

### 2. this 与 call/apply/bind（初级）

**主问：** this 的指向规则是什么？手写一个 bind。

**参考答案：** 指向优先级：new 绑定 > 显式绑定（call/apply/bind）> 隐式绑定（obj.fn()）> 默认绑定（严格模式下是 undefined，否则是全局对象）。箭头函数没有自己的 this，用的是定义时外层的 this。手写 bind 的要点：返回一个新函数；支持预先传入部分参数；被当作构造函数 new 时，this 要指向新创建的实例（用 `this instanceof bound` 判断），并且继承原函数的 prototype。

**追问：** bind 两次之后，this 以哪次为准？（第一次）

---

### 3. 原型链与继承（初级～中级）

**主问：** 说说原型链。ES5 怎么实现寄生组合继承？

**参考答案：** 每个对象都有 `[[Prototype]]`，也就是 `__proto__`，指向它构造函数的 prototype。访问属性时，自身找不到就沿着原型链往上找，直到 null。寄生组合继承分两步：在子类构造函数里 `Parent.call(this)` 继承实例属性；再 `Child.prototype = Object.create(Parent.prototype)`，并把 constructor 修正回 Child，这样就不会调用两次父类构造函数。ES6 的 class extends 本质上也是这个原理，只是要求先调用 super 才能使用 this。

**追问：** `instanceof` 的原理是什么？手写一个。

### 4. Promise 并发控制（中级）

**主问：** 手写一个函数，限制最多同时发 N 个请求，并按输入顺序返回结果。

**参考答案：** 维护一个结果数组和一个指针 idx；先启动 N 个 worker，每个 worker 循环做三件事：取出 `i = idx++`，执行 `await task()`，把结果写到 `res[i]`；最后 `await Promise.all(workers)`，然后返回 res。错误处理有两种语义可选：fail-fast 直接 reject，或者像 allSettled 那样把每个结果记成 `{status, value/reason}`。

**追问：** 如果还要支持重试和超时，你会怎么扩展？任务可以取消吗？（AbortController）

**定级：** 代码能一次跑通、边界处理清楚 → 中级。

---

### 5. 事件循环输出题（中级）

**主问：** 给一段混合 setTimeout、Promise.then、async/await 的代码，说出输出顺序并讲理由。

**参考答案：** 解题步骤：先按顺序执行同步代码；遇到 async 函数时，函数体在 await 之前的部分同步执行，await 之后的部分相当于放进 then，作为微任务；每执行完一个宏任务，就把微任务队列全部清空，然后才轮到下一个 setTimeout。Node 环境下还要注意 `process.nextTick` 比 Promise 微任务更早执行。

**追问：** `await` 一个已经 resolve 的 Promise，要多等几轮微任务？（新版 V8 只需 1 轮）

## 二面：框架与工程

### 6. React 渲染与优化（中级）

**主问：** 一个大表单页，输入时整页卡顿，你怎么分析和优化？

**参考答案：** 先用 React DevTools Profiler 找出是哪些组件在重复渲染、每次渲染花了多少时间。常见原因：状态放得太高，导致整棵树都跟着渲染；Context 的 value 每次都是新对象；列表很长却没有做虚拟化。优化思路：把状态下放到用到它的组件里，或者拆成多个 store 做细粒度订阅；需要时用 memo 并保证 props 引用稳定；表单改用非受控组件（如 react-hook-form）；昂贵的计算用 useDeferredValue 或 startTransition 降低优先级；长列表用 react-window 做虚拟滚动。

**追问：** useMemo 什么时候反而是负优化？

### 7. Vite 与构建优化（中级）

**主问：** 项目构建慢、首包体积大，你会怎么治理？

**参考答案：** 先做分析：用 rollup-plugin-visualizer 看产物里哪些模块最大，看构建耗时都花在哪个阶段。体积方面：路由级懒加载；三方库按需引入或换成更轻的替代品（比如 dayjs 替换 moment）；把公共依赖拆成单独的 chunk，充分利用浏览器缓存；图片转成 webp 或 avif。速度方面：用 esbuild 或 swc 替代 babel；开启缓存；monorepo 用 turborepo 做增量构建。最后在 CI 里加体积预算，超出就报警。

**追问：** modulepreload 有什么作用？chunk 拆得太碎会有什么问题？

---

### 8. 微前端（高级）

**主问：** 什么场景需要微前端？qiankun 是怎么做 JS 和样式隔离的？

**参考答案：** 适用场景：多个团队需要独立发布；老系统需要渐进迁移；技术栈不统一。qiankun 的 JS 隔离用 Proxy 沙箱：给每个子应用一个代理过的 window，激活和卸载时记录、还原对全局变量的修改。样式隔离有两种：Shadow DOM 严格隔离，或者给子应用样式加作用域前缀。它的代价是首屏性能、公共依赖会重复加载、跨应用通信更复杂。替代方案有 Module Federation，以及 iframe（隔离最彻底，但体验差）。

**追问：** 子应用之间共享登录态和公共依赖，怎么做？

**定级：** 能讲出不该用微前端的情况 → 高级。

## 三面：项目与综合

### 9. 项目亮点追问（中高级）

**主问：** 讲一个你做过最有技术挑战的前端项目，你具体负责什么，指标提升了多少？

**参考答案：** 回答可以用 STAR 结构：背景（业务规模、痛点）→ 你负责的部分 → 方案和取舍（当时考虑过哪些备选、为什么选这个）→ 量化结果（例如 LCP 从 3.2s 降到 1.4s，包体积减少 40%）→ 复盘（还可以怎么做得更好）。面试官主要看三点：是不是你本人主导的、有没有深挖原理、有没有数据支撑。

**追问：** 如果重新做一遍，你会改什么？这个方案在团队里是怎么推广落地的？

---

### 10. 前端稳定性（高级）

**主问：** 线上出现了白屏，你怎么在 5 分钟内发现、30 分钟内恢复？

**参考答案：** 发现：通过白屏检测（采样关键节点，或检查根节点是否为空）、JS 错误率告警、接口错误率告警，对接到值班系统。恢复：静态资源支持一键回滚到上一个版本；功能开关可以关掉出问题的模块；CDN 刷新缓存。定位：用 sourcemap 还原错误堆栈，按版本、浏览器、地域维度筛选，找出和发布记录的关联。事后：补上 ErrorBoundary 兜底、灰度发布，做复盘并制定改进项。

**追问：** sourcemap 怎么做到不暴露在公网上？（只上传到监控平台）
