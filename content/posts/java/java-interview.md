## 一、集合框架

### 1. ArrayList vs LinkedList（初级主问）

**主问：** 两者区别？什么场景用哪个？

**参考答案：**

- `ArrayList`：动态数组，随机访问 O(1)；尾部追加均摊 O(1)；中间插入/删除要搬移元素。  
- `LinkedList`：双向链表，头尾插入删除 O(1)；按下标访问 O(n)。  
- 实际业务绝大多数用 `ArrayList`；`LinkedList` 很少成为性能银弹，且常数更大、缓存不友好。  
- 扩容：`ArrayList` 大约按 1.5 倍扩（`old + old>>1`）。

**追问：**

1. 指定初始容量有什么好处？  
2. 多线程下 `ArrayList` 会怎样？用什么替代？  
3. `CopyOnWriteArrayList` 适合什么读写比？

**定级：** 说清数组 vs 链表取舍 → 初级过；能量化场景与 COW 代价 → 中级。

---

### 2. HashMap 原理（必考）

#### 初级

**主问：** `HashMap` 怎么存数据？`put` 大致流程？

**参考答案：** 数组 + 链表（JDK8+ 还有红黑树）。算 `hash` → 定位桶 → 空则放入；冲突则链上追加/树化；超过阈值按负载因子扩容。key/value 均可 null（一条 null key）。**线程不安全**。

**追问：** 为什么重写 `equals` 要重写 `hashCode`？

#### 中级

**主问：** 什么时候树化？扩容做了什么？为何容量是 2 的幂？

**参考答案：**

- 某桶链表长度 ≥ 8 **且** 数组长度 ≥ 64 时树化；否则优先扩容。树节点过少（≤6）会退回链表。  
- 扩容：容量翻倍，元素重新分布（高低位拆分），减少冲突。  
- 容量 2^n：可用位运算 `hash & (n-1)` 代替取模，更快且分布均匀依赖 hash 扰动。  
- 负载因子默认 0.75：空间与冲突的折中。

**追问：**

1. hash 扰动（`^ (h >>> 16)`）解决什么？  
2. 扩容时多线程会出现什么经典问题？（死链等，注意版本差异）  
3. 遍历时修改会怎样？（`ConcurrentModificationException` 快速失败）

#### 高级

**主问：** 线上 `HashMap` 相关事故你怎么防？何时必须换 `ConcurrentHashMap`？

**参考答案：** 共享可变 Map 必须并发容器或外部加锁；预估容量避免频繁扩容；key 的 `hashCode` 质量影响性能；大 Map 注意内存与 GC；不可用 HashMap 做分布式锁替代品。

**定级信号：** 树化条件说全 → 至少中级；能联系生产事故 → 高级倾向。

---

### 3. ConcurrentHashMap（中级）

**主问：** 和 `Hashtable` / 加锁 `HashMap` 比，它如何提高并发度？

**参考答案：**

- JDK7：分段锁 Segment。  
- JDK8+：节点级 CAS + `synchronized` 锁桶头，粒度更细；结构同样数组+链表/红黑树。  
- `size` 等用计数单元近似，追求并发性能。  
- **注意：** 复合操作（如「不存在则放入」）要用 `putIfAbsent` / `compute` 等原子 API，不能自己 get 再 put。

**追问：**

1. 为什么 key/value 不能为 null？  
2. `computeIfAbsent` 里再调用同一 map 可能怎样？（小心重入/死锁类问题）  
3. 遍历是强一致吗？

**定级：** 只说「分段锁」且不知 JDK8 变化 → 偏初级记忆；能讲清桶级锁 + 复合操作 → 中级。

## 二、并发与 JUC

### 4. 创建线程与线程状态（初级）

**主问：** 实现多线程有几种方式？状态有哪些？

**参考答案：**

- 常见：继承 `Thread`、实现 `Runnable` / `Callable`、线程池提交；本质是任务与执行解耦，**推荐池化**。  
- 状态：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED（不必死背英文，要能对应 wait/join/sleep/锁）。  

**追问：** `sleep` 和 `wait` 区别？（是否释放锁、作用在谁上）

---

### 5. synchronized vs Lock / volatile（中级主问）

**主问：** `synchronized` 和 `ReentrantLock` 怎么选？`volatile` 能代替锁吗？

**参考答案：**

- `synchronized`：JVM 内置，自动释放，锁升级（偏向→轻量→重量，细节随版本演进）；代码简洁。  
- `ReentrantLock`：可中断、可尝试、可公平、可多 Condition；需要显式 `unlock`（finally）。  
- `volatile`：保证**可见性**与有序性（禁止部分重排序），**不保证**复合操作原子性（`i++` 仍要原子类或锁）。  
- 能用 `java.util.concurrent` 原子类 / 并发集合时，优先比自己造锁。

**追问：**

1. 双重检查单例为什么要 `volatile`？  
2. 死锁四个必要条件？怎么用 `jstack` 查？  
3. 公平锁一定更好吗？

**定级：** 分清可见性 vs 原子性 → 中级线；能讲锁升级与生产排查 → 冲高。

---

### 6. 线程池（必考，分级问）

#### 初级

**主问：** 为什么用线程池？核心参数有哪些？

**参考答案：** 复用线程降开销、控并发、统一管理。核心参数：`corePoolSize`、`maximumPoolSize`、`keepAliveTime`、工作队列、`ThreadFactory`、`RejectedExecutionHandler`。

#### 中级

**主问：** 任务提交后完整执行流程？队列与最大线程谁先到？

**参考答案：** 线程数 < core → 建核心线程；否则进队列；队列满且 < max → 加非核心线程；再满 → 拒绝策略。  
**常见事故：** `Executors.newFixedThreadPool` 无界队列导致 OOM；`Fixed`/`Single`/`Cached` 要知道隐患，**生产建议手写 `ThreadPoolExecutor`**。  
拒绝策略：Abort、CallerRuns、Discard、DiscardOldest；业务常自定义打日志/落库/降级。

**追问：**

1. IO 密集和 CPU 密集怎么估线程数？  
2. 如何优雅停机？（`shutdown` vs `shutdownNow`）  
3. 线程池打满你怎么监控与扩容？

#### 高级

**主问：** 给订单核心链路定线程池规范：如何隔离、如何防雪崩？

**参考答案：** 按业务隔离池（核心/非核心）；有界队列 + 明确拒绝；与下游超时、舱壁、熔断配合；动态调参要有度量（活跃数、队列长度、拒绝次数）；禁止共用一个无限大池扛所有异步。

**定级：** 能背参数 → 初级；能讲提交流程与 Executors 坑 → 中级；能定隔离与指标 → 高级。

---

### 7. AQS / CountDownLatch（中高）

**主问：** AQS 是什么？`CountDownLatch` 和 `CyclicBarrier` 差别？

**参考答案：**

- AQS：队列同步器框架，维护 state + CLH 变体等待队列；`ReentrantLock`、`CountDownLatch`、`Semaphore` 等构建其上。  
- `CountDownLatch`：一次性倒数，主线程/等待方等计数到 0。  
- `CyclicBarrier`：可循环屏障，多方互相等齐。  
- `Semaphore`：许可数，控并发度。

**追问：** 能否不看源码讲清「抢锁失败后怎么排队、怎么被唤醒」？

**定级：** 说出谁用了 AQS → 中；能讲 state 与队列协作 → 偏高。

## 三、JVM

### 8. 内存区域（初级）

**主问：** 堆和栈有什么区别？方法区/元空间放什么？

**参考答案：** 栈：线程私有，帧里局部变量、操作数栈等；堆：对象实例，GC 主战场；元空间（Java 8+）：类元数据等，本地内存。程序计数器、本地方法栈了解即可。

**追问：** 逃逸分析、标量替换听说过吗？（加分）

---

### 9. GC（中级）

**主问：** Young/Old 为什么分代？G1 了解多少？

**参考答案：** 弱分代假说：朝生夕死对象多，新生代用复制类算法更划算；老年代存活久，标记整理/混合回收。G1：Region 化，面向软实时停顿目标，混合回收。ZGC：超低停顿，大堆场景常被提到。

**追问：**

1. Full GC 频繁怎么查？  
2. `OutOfMemoryError` 常见几种（堆、元空间、直接内存、无法创建线程）？  
3. 如何看 GC 日志定问题类型？

**定级：** 会分代名词 → 初级；能结合日志与调优目标 → 中高。更多见 [GC 入门](/posts/java/jvm-gc-basics/)。

---

### 10. 类加载与双亲委派（中级）

**主问：** 类加载过程？为什么要双亲委派？

**参考答案：** 加载 → 链接（验证/准备/解析）→ 初始化。双亲委派：优先让父加载器加载，避免核心类被篡改、保证唯一性。突破场景：热部署、SPI（`ServiceLoader` / JDBC 驱动）等。

**追问：** Tomcat 类加载器为何要打破部分委派？

---

## 四、Spring / Spring Boot

### 11. IoC / Bean 生命周期（初～中）

**主问：** IoC、DI 是什么？Bean 默认作用域？

**参考答案：** 容器管对象创建与依赖注入；默认单例。生命周期：实例化 → 属性注入 → Aware → 初始化（`@PostConstruct` / InitializingBean）→ 使用 → 销毁。AOP 常通过代理介入。

**追问：** 构造器注入 vs 字段注入你推荐哪个？为什么？

---

### 12. 循环依赖（中级）

**主问：** Spring 如何解决构造器/属性循环依赖？哪些解决不了？

**参考答案：** 单例 + 属性注入：三级缓存提前暴露工厂/早期引用。**构造器循环依赖无法通过三级缓存解决**，需重构或 `@Lazy`。多例、原型场景行为不同。

**追问：** 三级缓存各自放什么？为何需要第三级？

---

### 13. 事务失效（中级必考）

**主问：** `@Transactional` 什么情况下不生效？

**参考答案要点：**

1. 非 public 方法  
2. 同类自调用（没走代理）  
3. 异常被吞或抛检查异常未配置 `rollbackFor`  
4. 数据库引擎不支持事务  
5. 传播行为理解错误  
6. 没被 Spring 管理 / 错误的代理模式（部分切面）

**追问：** `REQUIRED` vs `REQUIRES_NEW`？大事务有什么危害？

**定级：** 能列 3 条以上失效场景并讲自调用 → 中级扎实。

---

### 14. Spring Boot 自动配置（初级～中）

**主问：** 为什么加依赖就能用？如何排除某条自动配置？

**参考答案：** `@EnableAutoConfiguration` + `spring.factories` / `AutoConfiguration.imports` 按条件装配；可用 `exclude`、配置属性、自定义 Bean 覆盖。详见 [Spring Boot 笔记](/posts/java/spring-boot-notes/)。

## 五、MySQL（Java 岗常问）

### 15. 索引与慢 SQL（初～中）

**主问：** 什么时候建索引？为什么有时索引不走？

**参考答案：** 高区分度、常出现在 WHERE/JOIN/ORDER；联合索引最左前缀。不走索引：函数包列、隐式转换、LIKE `%xx`、优化器判全表更优、数据量太小等。

**追问：** 覆盖索引、回表、索引下推是什么？`EXPLAIN` 看哪些字段？

---

### 16. 事务隔离级别（中级）

**主问：** 四种隔离级别与脏读/不可重复读/幻读？MySQL InnoDB 默认？

**参考答案：** RU / RC / RR / Serializable。InnoDB 默认 RR；通过 MVCC + 间隙锁等抑制幻读（表述抓大意即可）。RC 下更易用到新版「读已提交」行为，需结合 binlog 格式谈主从。

**追问：** 长事务的危害？如何排查持锁？

## 六、场景题（强定级）

### 17. 接口突然变慢（中）

**主问：** 线上接口 P99 从 50ms 飙到 2s，你怎么查？

**参考答案路径：**

1. 确认范围：单机还是集群、是否发布、依赖是否抖  
2. 指标：CPU、负载、GC、线程池队列、DB/Redis/HTTP 耗时  
3. 工具：APM、慢日志、`jstack`/`arthas`、`EXPLAIN`  
4. 常见因：慢 SQL、缓存击穿、连接池耗尽、Full GC、下游超时重试放大  
5. 止血：限流、降级、扩容、回滚；再根治  

**定级：** 有条理排查树 → 中级；能量化与预防机制 → 高级。

---

### 18. 线程池拒绝 / 队列堆积（中）

**主问：** 异步发短信线程池开始 RejectedExecution，怎么办？

**参考答案：** 看拒绝策略是否丢消息；扩容要评估下游；改有界队列 + 降级落库补偿；核心链路不要和边缘任务共池；加监控告警。

---

### 19. 设计一个幂等下单接口（高）

**主问：** 用户重复点击、消息重复投递，如何保证只下一单？

**参考答案要点：** 业务唯一键（订单号/幂等号）+ DB 唯一索引；Redis setNX 短窗；状态机；MQ 消费幂等表；与支付回调对账。讲清「至少一次投递」下的去重。

**追问：** 分布式事务你用过哪种？为什么不强上 2PC？

---

### 20. 缓存与 DB 一致性（高）

**主问：** 更新数据时先更新 DB 还是先删缓存？

**参考答案：** 常见「先更新 DB，再删缓存」；延迟双删、订阅 binlog 删缓存等变体。接受最终一致；强一致场景评估是否该走强依赖 DB 或分布式事务。防穿透（布隆/空值）、击穿（互斥/逻辑过期）、雪崩（过期打散）。
