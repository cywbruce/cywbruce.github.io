## 一、索引

### 1. 索引是什么？为什么快？（初级）

**主问：** 索引是什么结构？和全表扫描比为什么快？

**参考答案：** InnoDB 常用 **B+ 树**。叶子存数据行（聚簇）或主键值（二级索引）。有序、扇出大、适合范围查询；减少随机 IO。不是哈希（哈希不擅范围）。

**追问：**

1. 主键索引和二级索引差别？（聚簇 vs 非聚簇，回表）  
2. 为什么不建议用过长字符串当主键？  
3. 索引是不是越多越好？

**定级：** 说出 B+ 树 + 少 IO → 初级过。

---

### 2. 联合索引与最左前缀（中级）

**主问：** 索引 `(a,b,c)`，哪些 WHERE 能用上？`ORDER BY` 呢？

**参考答案：** 最左前缀：`a`、`a,b`、`a,b,c` 可；只有 `b` 或只有 `c` 通常用不上。范围条件后右侧列难以再高效用索引排序/过滤。覆盖索引可避免回表。

**追问：**

1. `a=1 AND c=3` 能用到哪几列？  
2. 索引下推（ICP）解决什么？  
3. 如何设计订单表常用查询的联合索引？

**定级：** 能独立举反例 → 中级。

---

### 3. 索引失效常见原因（中级）

**主问：** 明明建了索引却不走，可能为什么？

**参考答案：** 对列做函数/运算、隐式类型转换、`LIKE '%xx'`、优化器估全表更优、`OR` 一侧无索引、数据量太小、统计信息不准等。

**追问：** 怎么验证？看 `EXPLAIN` 哪些列？（`type`、`key`、`rows`、`Extra`）

## 二、事务与隔离

### 4. ACID 与隔离级别（初级～中级）

**主问：** 四个隔离级别分别解决什么问题？InnoDB 默认？

**参考答案：**

| 级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| READ UNCOMMITTED | 可能 | 可能 | 可能 |
| READ COMMITTED | 否 | 可能 | 可能 |
| REPEATABLE READ | 否 | 否 | 视实现 |
| SERIALIZABLE | 否 | 否 | 否 |

InnoDB 默认 **RR**；通过 MVCC + 间隙锁等抑制幻读（表述抓主流即可）。

**追问：**

1. 脏读、不可重复读、幻读各举一例。  
2. 为什么有人生产用 RC？和 binlog 格式什么关系？  
3. 长事务有什么危害？

**定级：** 表能填对 → 初级；能联 MVCC/锁 → 中级。

---

### 5. MVCC（中级）

**主问：** MVCC 怎么让读不加锁还能隔离？

**参考答案：** 每行隐藏列（事务号、回滚指针等）+ undo 构造历史版本；读视图（Read View）决定看见哪个版本。RR 与 RC 创建 Read View 时机不同（RR 常首次一致性读创建，RC 每条语句创建——以主流教材口径为准，可追问候选人是否知其版本差异）。

**追问：** 当前读和快照读差别？`SELECT ... FOR UPDATE` 属于哪种？

## 三、锁与死锁

### 6. 行锁、间隙锁（中级）

**主问：** InnoDB 有哪些锁？间隙锁防什么？

**参考答案：** 行锁、间隙锁、临键锁（Record + Gap）；表级意图锁。间隙锁主要防幻读、保护范围内插入。索引条件影响加锁范围；无索引可能升级到更多锁甚至表级影响。

**追问：** 更新条件不走索引时会发生什么？

---

### 7. 死锁（中级～高级）

**主问：** 死锁怎么产生？怎么查、怎么减少？

**参考答案：** 两事务互等对方持有的锁。InnoDB 会检测并滚掉一方。`SHOW ENGINE INNODB STATUS` 看死锁日志。减少：固定加锁顺序、缩短事务、合适索引减小锁范围、避免大事务、热点行拆分。

**追问：** 给一个「转账」或「扣库存」死锁例子，怎么改？

**定级：** 能讲排查命令 + 改法 → 中级扎实。

## 四、执行计划与优化

### 8. EXPLAIN（中级）

**主问：** 你平时怎么读执行计划？

**参考答案：** 关注 `type`（最好 ref/range，忌 all 且 rows 巨大）、`key` 是否符合预期、`rows` 估测、`Extra`（Using filesort / temporary / index）。先确认是否用对索引，再谈改写 SQL。

**追问：** `Using index` 和 `Using index condition` 差别？

---

### 9. 深分页（中高级）

**主问：** `LIMIT 1000000, 10` 为什么慢？怎么优化？

**参考答案：** 仍要扫描/排序大量行再丢弃。优化：基于上次最大 id 的键集分页（`WHERE id > ? ORDER BY id LIMIT 10`）；子查询先取主键再回表；业务限制翻页深度。

## 五、架构与运维向

### 10. 主从与延迟（中高级）

**主问：** 主从复制做什么？延迟怎么排查？

**参考答案：** 读扩展、备份、高可用。延迟常见：从库单线程回放（视版本）、大事务、DDL、硬件差、网络。读己之写可用：强制走主、会话一致性、等待位点。

**追问：** 主从数据不一致可能原因？GTID 有什么好处？

---

### 11. 分库分表（高级）

**主问：** 什么时候拆？按什么键拆？跨库查询怎么办？

**参考答案：** 单表过大、写入打满、运维窗口不够时再拆。选均匀且查询常带的分片键。跨库：避免、异步汇总、异构查询（ES）、应用层聚合。分布式事务慎用，优先最终一致与幂等。

## 六、场景题

### 12. 慢 SQL 治理（中）

**主问：** 线上慢 SQL 越来越多，你怎么系统性治理？

**路径：** 慢日志 → EXPLAIN → 加/改索引或改写 → 验证 → 规范（禁止无索引大表扫、强制 Code Review）。

### 13. 库存超卖（中高）

**主问：** 高并发扣库存出现超卖，用数据库怎么解决？

**路径：** 乐观锁 version、`WHERE stock >= ?` 更新行数、悲观锁、Redis 扣减 + 对账；结合事务与唯一约束。
