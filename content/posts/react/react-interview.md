## 怎么用这份提纲定级

| 级别 | 大致画像 | 回答特征 |
| --- | --- | --- |
| 初级 | 能独立做页面、改需求 | 会用 API，说得出「做什么」，机制偏模糊 |
| 中级 | 能设计组件与数据流、排常见坑 | 能讲清「为什么」，能举项目里的坑与解法 |
| 高级 | 能定规范、做性能与架构取舍 | 能谈权衡、边界、团队影响，不只会背概念 |

**加分：** 主动提失败案例、度量方式、与业务约束的取舍。  
**减分：** 只背名词、无法落到代码、把过时实践当唯一真理。

## 一、渲染与更新模型

### 初级

**主问：** 点击按钮后，React 怎么把界面更新出来？

**期望要点：** 事件 → `setState` → 调度再渲染 → Diff / 协调 → 提交到 DOM；函数组件会重新执行。

**追问：**

1. 为什么不能直接改 `state` 对象？  
2. 一次点击里调两次 `setCount(count + 1)`，结果是多少？（引出函数式更新）  
3. `key` 有什么用？列表里用 index 当 key 会有什么问题？

**定级信号：** 能串起「setState → 重渲染 → 虚拟 DOM 对比」即可。

### 中级

**主问：** 什么会触发重渲染？子组件怎样避免被父组件带着渲染？

**期望要点：** 自身 state / props / context 变化；父渲染默认子也渲染；`memo`、稳定 props、状态下沉 / 上提的取舍。

**追问：**

1. `memo` 包了子组件，父每次仍传内联 `onClick={() => ...}`，memo 还有用吗？  
2. Context 值变了，哪些消费者会更新？如何拆 Context 减渲染？  
3. `useState` 的初始值写成 `useState(createRows())` 和 `useState(() => createRows())` 差别？

**定级信号：** 能讲引用相等与渲染范围 → 中级。

### 高级

**主问：** 解释一下 Render → Commit；并发特性下「可中断渲染」对业务代码意味着什么？

**期望要点：** 渲染可重复执行须纯净；副作用进 Effect；`startTransition` / `useDeferredValue` 保交互优先；了解 tearing、已废弃的旧并发 API 勿混谈。

**追问：**

1. 为什么说「渲染阶段不要做副作用」？举一个并发下会出问题的例子。  
2. 什么场景用 `useTransition`，什么场景用防抖？  
3. 外部 store 订阅为何推荐 `useSyncExternalStore`？

**定级信号：** 能结合并发与纯度谈，不空谈 Fiber 名词 → 高级。

## 二、Hooks 体系

### 初级

**主问：** 常用 Hooks 分别解决什么问题？`useEffect` 和 `useLayoutEffect` 差别？

**期望要点：** `useState` 状态、`useEffect` 同步副作用、`useRef` 可变盒子 / DOM、`useContext` 跨层读值；Layout 在绘制前同步执行。

**追问：**

1. Hooks 为什么不能写在条件语句里？  
2. `useEffect` 空依赖、无依赖数组、有依赖，三种行为？  
3. `useRef` 改 `.current` 会触发渲染吗？

**定级信号：** API 用途清楚、知道规则。

### 中级

**主问：** 讲一次你踩过的 `useEffect` 闭包或依赖问题，怎么修的？

**期望要点：** 过期闭包、漏依赖、多余依赖导致循环；用函数式更新、正确依赖、拆 Effect、abort / 忽略过期请求。

**追问：**

1. 在 Effect 里需要最新 `props` 又不想反复订阅，怎么办？（ref 模式）  
2. 自定义 Hook 和「组件内一坨逻辑」如何划界？  
3. `useCallback` 的依赖变了，依赖它的 Effect 会怎样？

**定级信号：** 有真实排障路径 → 中级。

### 高级

**主问：** 你会如何审查团队里滥用 `useMemo` / `useEffect` 的代码？Effect 驱动的数据流有什么架构味道问题？

**期望要点：** Effect 不是「万能生命周期」；能派生的 state 不要再存一份；数据获取更倾向事件 / 路由 loader / React Query；memo 有成本，先量再优。

**追问：**

1. 「用 Effect 把 props 同步进 state」为什么通常是坏味道？例外是什么？  
2. 你们项目里哪些逻辑从 Effect 迁到了事件处理或库？收益是什么？  
3. React 19 的 `use` / 编译器方向，会怎样改变 Hooks 写法？

**定级信号：** 有架构品味与演进意识 → 高级。

## 三、性能优化

### 初级

**主问：** 列表卡顿时你首先会查什么？

**期望要点：** 渲染次数、列表长度、有没有多余 state、图片/重排；知道虚拟列表、分页的存在。

**追问：** 虚拟列表解决的是 DOM 多还是 JS 计算多？二者都可能时怎么拆？

### 中级

**主问：** 如何系统定位 React 性能问题？

**期望要点：** Profiler、为何渲染、`memo` 边界、状态粒度、昂贵计算、网络瀑布；避免过早优化。

**追问：**

1. `React.lazy` + `Suspense` 解决什么？错误边界怎么配？  
2. 大表单每个 keystroke 都卡，状态结构怎么改？  
3. 长列表 + 每行复杂组件，优化顺序怎么排？

### 高级

**主问：** 给一个中后台大表 + 图表页做性能预算，你怎么定指标与治理手段？

**期望要点：** INP/交互、首屏、内存；分区渲染、窗口化、Web Worker、选择性水合（若 SSR）；规范上禁止无必要全量 Context。

**追问：** 性能优化和可维护性冲突时你怎么决策？举例。

## 四、状态管理

### 初级

**主问：** 组件间怎么共享状态？什么时候用 Context？

**期望要点：** props 传递、提升 state、Context 适合低频、偏「依赖注入」的数据；不要把所有全局都塞 Context。

### 中级

**主问：** Redux / Zustand / React Query 各解决什么？你会怎么选？

**期望要点：** 客户端 UI 状态 vs 服务端缓存状态；Query 管请求缓存/重试/失效；Zustand 轻量；Redux 适合强规范、时间旅行、复杂更新规则。

**追问：**

1. 把接口数据既放 React Query 又拷进 Redux，有什么问题？  
2. 表单状态放 zod + RHF 还是全局 store？  
3. URL 状态（搜索、分页）要不要进 store？

### 高级

**主问：** 设计一版前端状态分层规范（本地 / 共享 UI / 服务端 / URL），并说明反模式。

**期望要点：** 单一数据源、失效策略、权限与模块边界、可测试；能画出团队落地检查清单。

**追问：** 微前端或多 SPA 共享登录态与主题，状态放哪？

## 五、组件设计与工程

### 初级

**主问：** 受控组件和非受控组件区别？什么时候用哪种？

**追问：** 文件上传为什么常见非受控？如何做成受控体验？

### 中级

**主问：** 如何设计一个可复用的 `Select` / `Modal`？API 怎么兼顾灵活与简单？

**期望要点：** 受控优先、插槽/`children`、可访问性、焦点陷阱、禁用滚动；避免上帝组件。

**追问：** 复合组件（Compound Components）和 render props / hooks 方案怎么选？

### 高级

**主问：** 从 0 定 React 技术栈与目录规范，一年后最容易烂掉的点是什么？你怎么防？

**期望要点：** 状态流混乱、Effect 滥用、类型 `any` 蔓延、样式与请求无标准；Lint、脚手架、Code Review 清单、示例仓库。

**追问：** RSC / Next App Router 若引入，对「组件纯客户端心智」冲击是什么？团队怎么培训？
