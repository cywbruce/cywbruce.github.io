## 场景 1：搜索框 + 分页列表（初级～中级）

**主问：** 输入关键词防抖搜索，带分页、加载中、空态、失败重试；快速输入时结果不能乱。

### 长参考答案（思路）

1. **状态拆分：** `keyword`（输入框即时）、`debouncedKeyword`（请求用）、`page`、`data`/`total`、`loading`/`error`。  
2. **请求层：** React Query / SWR；`queryKey: ['list', debouncedKeyword, page]`，自动处理缓存与竞态。  
3. **不用 Query 时：** 请求序号 / `AbortController`，只应用最新一次。  
4. **UX：** 输入中保留旧列表或 skeleton；失败可重试；空关键词是否回退默认列表要产品确认。  
5. **URL 同步（加分）：** `q`、`page` 进 search params，可分享可回退。

### 参考骨架

```tsx
const [keyword, setKeyword] = useState('')
const debounced = useDebouncedValue(keyword, 300)
const [page, setPage] = useState(1)

useEffect(() => setPage(1), [debounced]) // 关键词变重置页码

const { data, isLoading, isError, refetch } = useQuery({
  queryKey: ['items', debounced, page],
  queryFn: ({ signal }) => fetchItems({ q: debounced, page, signal }),
})
```

| 级别 | 定级信号 |
| --- | --- |
| 初 | 能想到防抖 + loading |
| 中 | 竞态 / Abort / queryKey |
| 高 | URL 同步、缓存失效、埋点与可访问性 |

**追问：** 输入法组合中（composition）要不要搜索？列表项点进详情返回是否保留滚动？

## 场景 2：复杂表单（多步 / 动态字段）（中级）

**主问：** 10+ 字段，部分联动（选省出市），提交校验，草稿保存。

### 长参考答案

1. **库：** React Hook Form + Zod（或 Formik）；避免每个 keystroke 引爆整树。  
2. **联动：** `watch` 字段 + `setValue`；或字段级订阅，减少全表渲染。  
3. **动态字段：** `useFieldArray`；key 用稳定 id。  
4. **校验：** schema 单源；服务端错误映射回字段。  
5. **草稿：** debounce 写 localStorage / 后端；注意敏感字段。  
6. **不要：** 把整个 form 塞进全局 Redux，除非跨页强共享。

| 级别 | 定级信号 |
| --- | --- |
| 初 | 受控输入 + 提交校验 |
| 中 | 性能（RHF）、联动、错误映射 |
| 高 | schema 单源、权限字段、草稿冲突合并 |

**追问：** 中途改「类型」导致整段字段卸载，未提交数据怎么处理？

## 场景 3：全局登录态与路由鉴权（中级）

**主问：** 未登录跳登录；登录后回跳；token 过期刷新；权限码控按钮。

### 长参考答案

1. **分层：** 认证（是谁）vs 鉴权（能做什么）。  
2. **存储：** 内存 + HttpOnly Cookie 更安全；LocalStorage 易 XSS。  
3. **路由：** loader / 路由守卫；别只藏按钮。  
4. **刷新：** 单飞（inflight promise）刷新 token，队列重放 401 请求。  
5. **权限：** 路由级 + 组件级；权限列表进 Context / 外置 store，注意渲染范围。

```txt
请求 401 → 尝试 refresh（共用一个 Promise）
         → 成功则重放原请求
         → 失败则清会话并跳登录（带 redirect）
```

| 级别 | 定级信号 |
| --- | --- |
| 初 | 有 token、路由跳转 |
| 中 | 刷新单飞、回跳、按钮+路由双控 |
| 高 | Cookie 方案、CSRF、权限模型、多 Tab 同步 |

## 场景 4：列表页卡顿（性能）（中级）

**主问：** 表格 2000 行，每行有按钮和标签，滚动卡、输入卡。

### 长参考答案

1. **先量：** React Profiler、Performance、是否主线程长任务、是否每次输入全表渲染。  
2. **结构：** 状态下沉；输入框独立组件；行 `memo`；回调稳定。  
3. **窗口化：** 虚拟列表（只挂载可视行）。  
4. **数据：** 分页 / 服务端筛选；别一次塞 2000 复杂对象到 Context。  
5. **绘制：** 减少每行 DOM、避免匿名 inline 大对象、图片懒加载。  
6. **验证：** 优化前后 INP / 滚动 FPS 对比。

| 级别 | 定级信号 |
| --- | --- |
| 初 | 会说虚拟列表、分页 |
| 中 | 先定位再优化、memo 失效原因 |
| 高 | 性能预算、指标、与产品的行数约束谈判 |

## 场景 5：详情页请求瀑布流（中级）

**主问：** 先拿用户，再拿订单，再拿物流，首屏很慢。

### 长参考答案

1. **并行：** 无依赖的请求 `Promise.all`。  
2. **后端聚合：** BFF / 聚合接口减往返（最佳）。  
3. **Suspense / 流式：** 骨架分区渲染；次要模块懒加载。  
4. **缓存：** 用户信息短缓存；点进详情预取。  
5. **优先级：** 首屏关键路径资源 preload。

**追问：** 用 RSC / loader 时数据放服务器还是客户端？如何避免水合后重复打接口？

## 场景 6：大文件上传（中高级）

**主问：** 500MB 视频，要进度、断点续传、失败重试。

### 长参考答案

1. 切片（如 5MB）+ 计算 hash（spark-md5 / worker，防卡 UI）。  
2. 询问服务端已传分片 → 只传缺失（秒传 / 续传）。  
3. 并发上限（如 3）+ 失败重试 + 进度聚合。  
4. 合并接口；校验完整 hash。  
5. 离开页面 `beforeunload` 提示；可暂停。

| 级别 | 定级信号 |
| --- | --- |
| 中 | 切片 + 进度 + 并发 |
| 高 | worker 算 hash、续传协议、弱网策略 |

## 场景 7：微前端 / 多团队样式与路由冲突（高级）

**主问：** 主应用 React，子应用也有 React，样式互染，登录态要共享。

### 长参考答案

1. **样式：** CSS Modules / 约定前缀 / Shadow DOM（代价大）/ 构建加前缀。  
2. **JS：** 运行时隔离（sandbox）、公共依赖 externals 版本对齐。  
3. **路由：** 主子路径约定、basename。  
4. **登录态：** Cookie 同域 或 主应用注入 token；避免各子应用各存一份互不同步。  
5. **发布：** 独立部署 + 契约（props / 自定义事件 / 全局状态总线）版本化。

**定级：** 能讲隔离与契约 → 中高；能量化治理成本 → 高级。

## 场景 8：线上 Bug「偶发白屏 / 状态错乱」（中高级）

**主问：** 无法稳定复现，怎么查？

### 长参考答案

1. **兜底：** Error Boundary + 上报（Sentry）；记录 release、用户路径。  
2. **线索：**  Sourcemap、复现机型、Feature flag、最近发布。  
3. **典型根因：** Effect 竞态、key 乱用导致状态复用、闭包旧值、并发模式下不纯渲染。  
4. **手段：** 日志埋点关键状态机；session replay；加断言。  
5. **修复：** 先止血（兜底 UI）再根治；补回归测试。

| 级别 | 定级信号 |
| --- | --- |
| 中 | 有排查路径与监控意识 |
| 高 | 能关联 React 并发/纯度、发布与回滚 |

## 场景 9：设计一个前端监控与性能体系（高级）

**主问：** 从 0 到 1，你要哪些指标、怎么采集、怎么推动治理？

### 长参考答案

1. **体验：** LCP、INP、CLS；业务：首屏可交互、接口成功率、JS Error 率。  
2. **采集：** web-vitals、性能标记、接口拦截、资源 timing。  
3. **维度：** 页面、版本、地区、设备、采样率。  
4. **治理：** 预算门槛卡 CI；周报 Top 劣化页；专人认领。  
5. **忌：** 只堆 SDK 不看数；指标没有 owner。

## 场景 10：AI 辅助开发（中级）

**主问：** 你怎么用 Copilot / Cursor 写业务？如何保证质量？

### 长参考答案

1. **用途：** 样板、单测、重构建议、文档；不把生成代码当真理。  
2. **流程：** 生成 → 人审（安全、边界、类型、无障碍）→ 测试 → 再合入。  
3. **风险：** 幻觉 API、泄露内部代码到不当上下文、依赖过时写法。  
4. **团队：** 约定 Prompt 模板、禁止提交未审 AI 大段代码、Code Review 清单加一条「AI 产物」。

| 级别 | 定级信号 |
| --- | --- |
| 中 | 有使用经验 + 审查意识 |
| 高 | 能定团队规范与风险控制 |
